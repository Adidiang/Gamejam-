# 灵感涌现ing

经营一个游戏开发社团，用十二个月把脑洞变成自己的作品。

基于 **Godot 4.7.2 / GDScript** 制作。当前默认入口为新的界面骨架：开始页的两个初始员工选择框与“开始游戏”按钮、以活动室背景图铺满、为十名候选员工预留的矩形入口（只显示已加入者）、显示四项能力（白值与绿色增幅后两列，每点好感 +1%）、好感度（上限 50）和三个技能位的人物资料页，以及主界面右上角的年月与其下方的全局灵感点数显示、画面下方排期按钮左侧的当前作品名字与类型题材及作品四项属性（游戏性、创新性、表现力、Bug），以及右下角“排期”打开的工作分配表（拖动角色圆形或点击拿起再点击放下，调整玩法、美术、音效、修复四项职责）。排期中的“下一回合”结算全员岗位工作并推进月份，随后自动滚动展示左侧头像与右侧产出动效，展示结束后返回主界面；十二月展示结束后进入年末评奖界面，先提示 Bug 判定结果（命中时获得作品特质“BUG灾难”），再按“最佳游戏提名 → 最佳美术 → 最佳游戏”的顺序依次弹出本年所得奖项，每个奖项页只显示奖项名称与该奖项的灵感数量，没有奖项时只显示未获奖，确认后先逐人展示年初加入事件，再进入下一年的游戏选择页。岗位工作与任务都由成员属性算出产出，产出先经过统一的数值转换单元（3 个 0.5～1.5 随机数的平均值）再叠加技能加成与翻倍，顺序固定为「计算规则 → 转换单元 → 其他 buff」，公式见工程 README。

候选员工默认未招募；开始界面先选择两名不同员工，点击“开始游戏”时这两人直接加入社团，再进入第一年项目选择。点击任一选择框会用 5 列 × 2 行紧凑网格展示全部十人的立绘和名字，无需滚动；另一框已选员工置灰且不可重复选择，两框都选好后才能开始。底层仍支持无人社团推进月份并获得每月灵感。每年评奖结束后，只依据上一年作品的类型和题材匹配未加入者；至少命中一项即可，无人则跳过，一人加入一人，两人都加入，超过两人随机抽取两人。加入窗口逐人显示人物表的 `join_text`，空白时显示“加入文本”，确认后入社；全部确认后才进入新一年立项。未加入者不提前积累好感、不触发技能或获得团队成长。当前只有 a 配置了奇幻／科幻喜好，其余人的喜好保留空白。

人物页的“分配任务”打开右侧任务列表，支持美术概念设计：通用确认框取消后留在列表，确认后消耗 1 点回合行动步数，显示立绘和持续 1 秒的进度条，再只展示任务产出。任务不推进月份、不结算职责或获得每月灵感；通过排期中的“下一回合”统一结算并推进月份。全社团每回合隐藏的行动步数默认为 1，耗尽时“分配任务”按钮变灰，点击弹出“本回合已行动”小框，点击任意位置或 2 秒后自动关闭，下一回合恢复为 1，不累积。每年全社团只能执行一次此任务，次年恢复次数。表现力产出为增幅后的脑洞＋美术，创新性为该值×clamp(脑洞÷max(美术, 1), 0.1, 2)，系数限制仅适用于此任务。

人物页另有“邀约”按钮，与任务共享回合行动步数。确认后复用立绘与 1 秒进度条展示邀约结果，不推进月份或结算职责。邀约固定增加 10 好感，连续邀约同一人也为 +10，好感上限 50；邀约无年度次数限制，下一回合恢复步数后可再次执行。任一行动耗尽步数后，两个按钮都变灰，点击弹出“本回合已行动”小框。

## 运行游戏

1. 安装 Godot 4.7.2，使用普通版或 .NET 版均可；本工程使用 GDScript。
2. 导入 [`灵感涌现ing/project.godot`](./灵感涌现ing/project.godot)。
3. 按 **F5** 全屏运行，在两个选择框中选好不同员工后点击“开始游戏”，再在全屏游戏选择页自由输入作品名，并各选一种类型和题材，确认后进入主界面。第一年从所选的两名员工开始经营，可点击排期中的“下一回合”推进月份；上一年作品的类型或题材命中候选人的喜好时，次年年初最多加入两人。加入后点击对应人物矩形进入资料页；点击“关闭”返回主界面。点击右下角“排期”打开工作分配表调整职责，点击弹窗外的部分返回；点击“下一回合”推进月份并查看逐人工作产出，结束后点击“确认”。十二月工作确认后自动进入下一年的游戏选择页。可用 Alt+F4 退出游戏。

Windows 本机也可双击 [`灵感涌现ing/启动游戏.cmd`](./灵感涌现ing/启动游戏.cmd)。启动器优先使用开发机 D 盘的 Godot 4.7.2，保留 F 盘候选路径；其他成员请直接使用 Godot 导入，或修改 `灵感涌现ing/tools/launch.ps1` 中的路径。

每年的名字、类型、题材作为独立作品档案保存在模型的 `annual_projects` 中，使用固定类型／题材 ID，历史年份不被新作品覆盖；年末评奖的产出快照、分数、奖项与「BUG灾难」特质保存在 `annual_results`，跨年只把上一年的结果归档，新作品的属性与 Bug 从零开始。界面、技能与工作报告共用模型读取接口，完整结构和保存约定见工程 README 的“年度作品资料”。默认新界面尚未接入玩家自动存档／继续游戏入口，作品档案与评奖档案已通过现有存档层的保存与恢复测试。

新人物资料统一填写在 [人物表](./灵感涌现ing/data/characters.json)，字段说明见 [填写指南](./灵感涌现ing/data/README.md)。人物 a 已填入绵羊梦游者“代号sheep”，编程／脑洞／美术／音乐为 10／100／20／10，题材偏好为奇幻、科幻。三个技能已接入：白日梦自动生效，自己的月末工作或任务有 50% 概率睡着并取消产出，任务仍扣行动步数但保留年度次数；梦境讲述在 20 好感后花 10 灵感习得，每次睡着使自己脑洞白值 +10、其他在岗社员 +5；梦想家在 50 好感后花 20 灵感习得，睡着给当前项目建立不叠加的下一次任务翻倍标记，任意社员成功完成任务可使用。成长本局跨年保留，项目标记跨年清除，新游戏不继承。其余九人仍为零能力占位。[技能系统](./灵感涌现ing/scripts/skills/README.md)说明具体配置与结算；[绵羊技能测试](./灵感涌现ing/tests/test_sheep_skills.gd)验证取消、成长、翻倍、预览一致与保存恢复。

灵感由社团共享，初始 2 点、每回合获得 1 点，技能消费同一余额，年末评奖会额外发放：最佳游戏提名 +20、最佳美术 +30、最佳游戏 +50，三项可同时获得。Bug 只记录增加与修复（主界面下方实时显示游戏性、创新性、表现力与 Bug 的累计值），不影响每月产出与结算；但年末会按结算后的 Bug 数量判定「BUG灾难」，命中后该作品的各分项与各项之和减半，详见工程 README 的年末评奖说明。

开发版主界面左上角另有“调试”按钮（**F8** 也能开关）：可以给当前作品叠加或直接设定游戏性、创新性、表现力与 Bug，把当前时间跳到本年更晚的月份（**跨年与回退被拒绝**，且不补算跳过月份的产出与灵感），以及默认开启的全员满好感模式。满好感沿用现有规则提供每点 1% 增幅并解锁 20／50 好感技能位，但不免费习得技能，关闭时按开启前记录的好感恢复。打包正式版只需把 [`scripts/debug/debug_config.gd`](./灵感涌现ing/scripts/debug/debug_config.gd) 的 `ENABLED` 改成 `false`：调试按钮、面板、快捷键与底层入口一起失效，导出到 Release 模板还多一道自动保险。细节见工程 README 的“调试功能（开发版）”。

## 协作说明

提交源码、场景和 Godot 资源标识文件；不要提交 `.godot` 缓存、`saves` 存档、`qa` 测试截图、日志和导出包。相关排除规则已包含在 `.gitignore` 中。

人物立绘由人物表中的资源路径读取，主界面背景取自 `assets/backgrounds/`。中文显示使用本机系统字体；跨平台发布前需要配置可分发的中文字体。
