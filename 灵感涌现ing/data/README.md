# 人物表填写说明

`characters.json` 是人物资料的唯一来源。修改后重新运行游戏即可生效，无需修改界面代码。文件使用 UTF-8 编码。

人物 a 已按 [`角色属性与技能/绵羊梦游者.txt`](../角色属性与技能/绵羊梦游者.txt) 填入“代号sheep”：编程 10、脑洞 100、美术 20、音乐 10，题材偏好为奇幻、科幻。资料未指定类型偏好、初始好感或其他修正，分别保留空文本、0 和空文本。b、c、d 仍为零能力占位；a、b、c 的立绘已配置为 `res://assets/portraits/a.png` 等，d 的立绘为空。界面会将空姓名显示为“人物b”等。技能定义独立填写在 `skills.json`。

绵羊梦游者的三个技能目前仅填写名字“白日梦”“梦境讲述”“梦想家”，介绍、吐槽和触发器留空，费用保留 0，不接入睡着、成长、翻倍或灵感习得机制。人物页将这种仅有名字的技能标为“机制待实现”。题材偏好暂在 `preferred_topic` 中以“奇幻、科幻”展示，当前年度流程未接入偏好好感奖励。

| 字段 | 内容 |
| --- | --- |
| `id` | 唯一人物编号，建立后保持稳定 |
| `name` | 人物姓名 |
| `attributes.programming` | 编程能力，非负数 |
| `attributes.imagination` | 脑洞能力，非负数 |
| `attributes.art` | 美术能力，非负数 |
| `attributes.music` | 音乐能力，非负数 |
| `affinity` | 初始好感度，0～50 的整数，目前为 0 |
| `preferred_genre` | 喜欢的游戏类型，空文本表示未填写 |
| `preferred_topic` | 喜欢的题材，空文本表示未填写 |
| `skills` | 三个技能位；各包含 `skill_id` 和好感度门槛 `unlock_affinity`，按编号对应 0、20、50 |
| `other_modifiers` | 策划案中的“其他修正”，暂为说明文本，显示在人物页，不参与数值结算 |
| `portrait` | 一张立绘的工程资源路径；空文本表示未配置 |

好感度上限为 50，随机偏好匹配、邀约与技能加成都不会让好感超过上限。技能门槛按用户最新要求为 0、20、50，每人三个技能位，技能 4 与对应好感门槛 100 已删除。`skills.json` 保存名字 `name`、技能介绍 `description`、吐槽 `quip`、习得类型、费用和代码效果配置。`acquisition = auto` 达到门槛自动生效且费用为 0；`acquisition = inspiration` 在解锁后支付该技能配置的正整数 `inspiration_cost` 习得。费用不统一固定为 6。绵羊梦游者目前只填技能名字，其余人物技能文案仍留空，不自动生成角色技能。

完整字段、触发点和填写示例见 [技能系统指南](../scripts/skills/README.md)。付费学习不消耗月份，界面会显示未解锁、灵感不足和已习得等状态。实际结算已接入立项、单人任务、全员职责及评奖流程。

## 能力数值分层

人物页的四项属性按两层显示，填写新加成前先判断它属于哪一层：

| 数值 | 含义 | 代码入口 |
| --- | --- | --- |
| 白值 | 人物表 `attributes` 的基础属性，加上所有**直接增加数值**的加成 | `ClubGame.base_ability()` |
| 增幅合计 | 所有**百分比加成**相加，目前只有好感增幅 | `ClubGame.ability_bonus()` |
| 增幅后 | 白值 × (1 + 增幅合计)，人物页用绿色显示 | `ClubGame.ability()` |

直接加值计入白值，百分比计入增幅合计，两者不重复计算：百分比只对白值乘一次，不会被直接加值再次放大，直接加值也不会被百分比放大。当前好感增幅为**每点好感 1%**，好感上限 50 时最高 +50%。后续技能的百分比增幅写进 `ability_bonus()`，直接加值写进 `base_ability()`；技能百分比接入前，`ability_bonus()` 只返回好感增幅。

## 添加立绘

将可使用的图片放入 `assets/portraits/`，让 Godot 导入，然后将该人物的 `portrait` 填为例如 `res://assets/portraits/a.png`。主界面入口和人物页读取同一张立绘，保持图片比例完整显示；主界面里配好立绘的入口默认除立绘外全透明，不再画白底矩形、边框和焦点框，人物会直接站在活动室背景上，所以立绘轮廓之外要保持透明；没配立绘的入口保留编号矩形，人物页缺图时显示“立绘待添加”。不要把 Windows 绝对路径填入表中。素材格式与目录划分见 [`assets/README.md`](../assets/README.md)。

## 添加或替换人物

复制 `characters` 中的一条记录，修改为新的唯一 `id` 并填写内容。为新人物在 `skills.json` 添加三条技能定义，并将人物的三个 `skill_id` 指向它们；也可引用已经定义的技能，学习状态仍按人物独立保存。`initial_members` 按顺序指定四个主界面矩形对应的人物编号；例如换成 `["a", "b", "c", "e"]`，第四个入口就会读取人物 e。表中可以保存更多人物，但主界面保持四名在岗人物。

旧原型也读取此表。目前仅绵羊梦游者填写了能力，其余人物待填写，完整阵容尚需进行平衡验证。旧版本玩家存档不再加载，存档文件本身保留。

JSON 属于普通文件；将来导出游戏时，在 Godot 导出设置的非资源文件过滤器中包含 `data/*.json`。
