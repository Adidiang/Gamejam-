# 灵感涌现ing

Godot 4.7.2 / GDScript 原生游戏。唯一入口是新的界面骨架主场景 `scenes/interface_shell.tscn`；旧原型场景、脚本与测试已全部删除，项目只保留这一条新游戏流程。

## 当前界面入口

- 数值显示统一向下取整且不保留小数（如 12.9999 显示 12、−1.2 显示 −2），由 `scripts/number_display.gd` 负责。主界面作品属性、人物白值与增幅后能力、工作递增动画与总计、任务／技能成长结果、调试当前值与反馈共用此规则；总计先将真实数值相加再取整。只在生成文字时处理，模型、结算、技能、评奖和存档仍保留原有精度，调试输入也仍接受小数。
- `scenes/interface_shell.tscn` 为默认主场景，`scripts/interface_shell.gd` 管理界面切换。
- 开始界面包含两个初始员工选择框与“开始游戏”按钮。点击任一框会打开 5 列 × 2 行的员工网格，十人同时可见，无需滚动，每格只展示立绘和名字；缺立绘的区域留空。另一框已选员工会置灰且不可选，重新选择会释放旧人选。两个框都选好不同员工后才能开始，选择过程中不改变游戏状态。
- 点击开始时，两名所选员工直接加入社团，使用人物表初始好感，不弹年初加入窗口，然后进入全屏游戏选择界面：自由输入作品名，名字不截断；类型为 ACT、射击、RPG、策略、模拟经营、剧情向，题材为奇幻、科幻、现代、历史、惊悚。两组各单选一个，支持切换和实时预览；空白名字或选项未完成时不能确认，确认时去掉名字两端空白。确认立项时仅对已招募成员按显示名匹配偏好，命中一项加 10 点好感，选择页会实时显示本次选择谁会加好感。前两年十二月完成工作展示（无人跳过）、评奖与加入事件后进入下一年的选择页，第三年评奖后进入结算，清空草稿；未确认时不能进入排期、人物互动或推进月份。
- 选择确认后进入全屏主界面，为人物 a～j 保留十个可点击矩形，只显示已招募员工，背后铺满活动室背景图。已配置立绘的人物把立绘显示在矩形内并保持比例完整显示，入口默认除立绘外全透明（不画卡片底色、边框和焦点框），只在鼠标悬停时把光标变成手型；未配置立绘的人物保留编号矩形。
- 主界面背景由 `scenes/interface_shell.tscn` 里 `MainScreen/Background` 这个 TextureRect 节点承载，取自 `assets/backgrounds/clubroom.png`，保持比例铺满画面并裁掉多余部分；因此在编辑器里打开该场景就能对着背景图调人物矩形（`MainScreen` 默认隐藏，调布局时先在检查器里勾上 Visible，调完再取消并保存）。`scripts/interface_shell.gd` 启动时把图片写进该节点，图片缺失或资源类型不对时只输出警告、隐藏该节点并回退纯色底，不报错。开始页与人物页暂时使用纯色底。
- 人物入口的立绘由 `scenes/interface_shell.tscn` 里 `MainScreen/CharacterA`～`CharacterJ` 下的 `Portrait` 子节点承载，`scripts/interface_shell.gd` 启动时按人物表路径写入。配好立绘的入口由该文件的 `_style_portrait_button()` 改成除立绘外全透明，没有立绘时隐藏该子节点、保留原矩形与编号文字，不报错。默认不画焦点框，把 `scripts/interface_shell.gd` 里的 `PORTRAIT_FOCUS_HINT` 改成 `true` 可给键盘／手柄焦点加一圈金边。
- 人物资料统一填写在 [`data/characters.json`](./data/characters.json)，字段与添加方式见 [`data/README.md`](./data/README.md)。人物 a 已按绵羊梦游者资料填入“代号sheep”，编程 10、脑洞 100、美术 20、音乐 10，题材偏好为奇幻、科幻；初始好感为 0，未指定的类型偏好和其他修正留空。白日梦、梦境讲述、梦想家已接入真实结算，费用分别为 0、10、20 灵感，门槛为 0、20、50 好感；具体规则见下文。b～j 仍为空白、零能力占位；a、b、c 已配置立绘，d～j 尚未配置。
- 人物页显示编程、脑洞、美术、音乐、好感度、偏好、三个技能位、其他修正和一张立绘。四项属性各显示两列：第一列“白值”是人物表基础属性，第二列“增幅后”用绿色显示计算增幅后的最终值，悬停卡片可看到计算说明。每个技能分别显示名字、介绍和吐槽；吐槽是人物页专属文案，本月工作、任务／邀约结果、主界面提示等其他界面只显示技能名字。其他修正仍为说明文本；立绘路径为空时显示占位区域。
- 新界面的状态由 `ClubGame.fresh()` 初始化，好感度初始为 0、上限 50。能力分两层：`ClubGame.base_ability(member_id, state)` 返回「人物表基础属性 + 成员本局 `ability_growth`」；`ClubGame.ability_bonus()` 汇总百分比增幅，目前是好感增幅（每点好感 1%，满好感 +50%）；`ClubGame.ability()` 用「白值 × (1 + 增幅合计)」得到最终值，打开人物页时刷新。直接成长先并入白值，再统一乘一次增幅。
- 每人三个技能位，按用户最新要求在 0、20、50 好感度解锁，原来的技能 4 与 100 门槛已删除。自动技能达标生效，付费技能显示按配置消耗灵感的习得按钮，不消耗月份。技能填写与代码架构见 [技能系统指南](./scripts/skills/README.md)。点击“关闭”返回主界面。
- 默认全屏启动，按屏幕比例自适应布局；Alt+F4 可退出。
- 主界面右上角显示“第 x 年 x 月”，直接读取 `ClubGame.fresh()` 的年份与月份，不跟随系统时间，点击排期中的“下一回合”时推进月份，前两年 12 月后日历进入下一年 1 月，第三年 12 月后停在终局。
- 时间下方显示社团当前拥有的灵感点数。灵感是可获得、累积及消费的全局整数资源，保存在状态根字段 `inspiration`，不属于人物或作品；定义集中在 `ClubGame.INSPIRATION`。初始 10 点；月末每位已加入成员按增幅后脑洞 ÷ 100 的概率获得 1 点灵感（概率限制在 0～100%，脑洞达到 100 必得，每人每月最多 1 点），四种岗位规则相同，睡着者不产灵感，无人社团不产灵感。灵感上限 10000 点。`gain_inspiration()` 与 `spend_inspiration()` 提供不消耗月份的获得／消费入口，拒绝负数及余额不足的消费；技能、奖励和每月结算共用同一余额，获得或学习技能后刷新显示。
- 主界面下方显示当前作品：第一行是作品名字与类型题材（读当年作品档案 `annual_projects` 的 `title`／`genre_id`／`topic_id`，经 `GameCatalog.display_name()` 换成显示名），第二行是游戏性、创新性、表现力与 Bug 四项属性。数值只读自模型 `work` 快照，界面不参与结算；表现力就是 `work.p`，作品累计只在主界面属性栏显示（本月工作底部只汇总本回合全员产出）。属性栏排在右下角“排期”按钮左侧，随 `refresh_time()` 与年月、灵感一起刷新，结算、任务产出、进入主界面与每年立项后都会同步，不遮挡排期按钮或人物入口。
- 主界面右下角“排期”按钮打开工作分配表。职责调整不消耗月份、不触发结算，只改变本轮结算时各岗位的人选。
- 工作分配表是居中、非全屏的弹窗：背景压暗并被遮罩挡住下层输入，四个职责方框横排、名称显示在方框上方，角色用圆形的编号表示。拖动圆形，或点击拿起后再点击放下，两种方式都能移动；只要圆形中心落在某个方框内就调整职责（方框四边同样算落点），落在框外或被规则拒绝时回到拿起前的位置。没有拿起角色时点击界面外关闭，拿起后点击界面外先取消再关闭，拖到界面外松开则回到原位并保持弹窗打开，按 Esc 或右键取消拿起。
- 职责调整由 `ClubGame.assign()` 判定：立项准备和每月准备阶段都能自由调整，报告与结局阶段会被拒绝；新界面的岗位结算不隐式选择成员任务或触发立项，仍保留当前可调整阶段；工作展示期间遮挡下层入口并阻止再次结算。
- 工作分配表右下角“下一回合”关闭排期、一次性结算全员岗位产出并推进日历，然后打开“本月工作”。标题标注刚结算的年月；左侧按人物表顺序排列头像（无立绘时显示编号），右侧显示职责以及游戏性、创新性、表现力、Bug、修复能力（前三项一行、Bug 与修复一行）。下一人的数值先从零递增到完整成果，再开始滚动；滚动前上下两人的工作成果均已展示完成，每人的停留等待为 0.375 秒，全部完成后可点击“确认”；列表也可滚动回看。Bug 产出为 0 时不显示该项（成员成果与本月总计均适用）；修复能力显示原始贡献，实际 Bug 按全员同时结算并以零为下限，底部显示本回合全员产出总计（五项相加）与本轮获得／当前拥有的灵感，不显示作品累计值。未填能力的人物仍完整播放零产出。
- 岗位产出公式（用好感增幅后的最终属性，每月结算一次）：玩法开发 `游戏性 +0.7 编程 + 0.5 脑洞`、`创新性 +1.2 脑洞`、`Bug +max(0, floor((脑洞 − 编程) × 0.1))`；美术开发 `表现力 +0.8 美术 + 0.2 脑洞`、`创新性 +0.3 美术 + 0.2 脑洞`；音乐开发 `表现力 +0.8 音乐 + 0.2 脑洞`、`游戏性 +0.3 音乐 + 0.2 脑洞`；Bug 修复 `Bug −1 × 编程`。作品属性只有游戏性、创新性、表现力与 Bug 四项，表现力由岗位和任务直接写入 `work.p`，`ClubGame.performance()` 就是读取这个字段。
- 数值转换单元：任何由属性算出的产出都按「计算规则 → 转换单元 → 其他 buff」的顺序处理，同一份产出只转换一次，之后的技能加成与翻倍不再重复换算。系数取 3 个 0.5～1.5（含端点）均匀随机数的平均（Irwin–Hall 近似），整份产出乘以同一个系数并把结果量化到 4 位小数（存档 JSON 往返后数值一致）。岗位系数按 `本局 ID + 年月 + 成员` 生成，任务系数再带上任务 ID，因此预览、重复结算与读档结果一致；入口为 `ClubGame.output_factor()`、`duty_output_factor()`、`task_output_factor()` 与 `transform_output()`。旧原型的单人行动仍使用它自己的旧公式，不经过转换单元。
- 十二月的工作展示确认后不再直接进入次年选择页，而是打开全屏的年末评奖界面：先进行 Bug 判定，命中时弹出“收到玩家反映，大量BUG造成了灾难性的体验......”并说明作品获得特质“BUG灾难”（计算该游戏分数时各分项与各项之和各乘 0.5）；随后按“最佳游戏提名 → 最佳美术 → 最佳游戏”的顺序依次弹出本年所得奖项，每个奖项页只显示奖项名称与该奖项的灵感数量（如“灵感 +20”）；未获得的直接跳过，没有奖项时只显示一页“本年度未获奖”且不显示灵感，前两年确认后逐人展示年初加入事件，再进入下一年的游戏选择页；第三年最后一页为“结算”，点击进入两页三年结算。
- 年度评奖在 `ClubGame.advance_work()` 的十二月结算里一次算完并写入 `annual_results`：先判定 BUG灾难，再派发 `AWARD_BEFORE` 修正分项，接着判断奖项，最后派发 `AWARD_AFTER` 发放灵感。奖项门槛与奖励为：三项之和达到 3000 获最佳游戏提名并奖 20 灵感，表现力达到 4000 获最佳美术并奖 30 灵感，游戏性与创新性之和达到 10000 且表现力达到 2000 获最佳游戏并奖 50 灵感；三项可同时获得。灵感奖励在结算时直接计入社团余额，评奖界面只负责展示奖项与对应灵感；同一作品不会重复抽取判定，重新打开界面也不会再次发奖。
- 年度评分直接使用作品属性，1:1 换算、不折算成百分制：分项就是游戏性、创新性、表现力的当前数值，最佳美术看的就是表现力（美术与音乐岗位产出的都是表现力）。
- 前两年评奖结束后进入下一年时，作品属性与 Bug 归零，成员成长、好感度、已习得技能与社团灵感保留；历史作品的产出、分数、奖项与特质归档在 `annual_results`，可用 `ClubGame.annual_result_for_year()` 读取。
- 人物页的“分配任务”打开右侧部分宽度的任务列表，人物页保持可见；点击列表外任意位置只关闭列表、返回人物页，不触发背后的按钮。列表显示当年所有可用任务，已完成任务对全员隐藏，无任务时显示空状态。
- 选择任务调用 `TextConfirm.ask()`：取消只关闭确认框，确认关闭确认框与任务列表并打开执行界面。执行界面左侧为执行成员立绘（缺图显示编号），右侧先保持空白，下方真实进度条在 1 秒内从 0 到 100，完成后只显示本次任务产出及任务技能带来的实际变化，不显示职责产出或每月灵感。播放时不能提前关闭或重复执行；完成后点“确认”返回主界面。
- 按用户最新规则，全社团每回合有隐藏的行动步数，默认为 1。任务消耗 1 步，但不推进月份；步数为 0 时，所有成员的“分配任务”按钮变灰，点击弹出“本回合已行动”小框，点击任意位置或 2 秒后自动关闭，不能打开列表。排期中的“下一回合”仍是月份推进入口，同时结算全员职责、获得每月灵感、把行动步数恢复为 1；未用的步数不累积，玩家也可以未行动直接进入下一回合。
- 当前任务只有“美术概念设计”，无前置、消耗 1 行动步数。每款游戏（按年份）全社团只能执行一次，换成员或下个月恢复步数不会恢复任务次数，排期跨年后才恢复。产出使用好感增幅后的属性：表现力＝脑洞＋美术；创新性＝表现力×clamp(脑洞÷max(美术, 1), 0.1, 2)。分母最低取 1，系数最低 0.1、最高 2，均为用户确认的规则；系数限制仅适用于此任务。
- 隐藏步数保存在根字段 `action_steps`。任务次数保存在可选根字段 `completed_tasks`，按年份键记录任务 ID；表现力保存在 `work.p`（岗位与任务都会写入）。`ClubGame.execute_task()` 统一校验余额、次数、阶段和预期年月，只结算任务及任务阶段技能、扣减步数；界面只播放已确定的报告。`advance_work()` 负责职责、每月灵感、日历推进与步数重置，`available_tasks()` 提供列表。
- 人物页新增与“分配任务”并排的“邀约”按钮。点击后使用通用确认框，取消留在人物页且不消耗步数；确认后调用 `ClubGame.execute_invite()`，与任务共用一次行动结算及执行展示界面，左侧立绘、右侧先空白、下方 1 秒进度条，完成后显示好感变化及邀约技能带来的实际变化。执行后返回主界面，年月保持不变。
- 邀约与任务共用全社团 `action_steps`：任一行动消耗 1 后两个按钮均变灰，点击均显示“本回合已行动”小框（点击任意位置或 2 秒后消失）。邀约不结算职责或每月灵感，不登记年度任务次数，恢复步数后可在同年再次邀约。好感由 `invite_gain()` 固定增加 10，连续邀约同一成员或更换成员均不改变增量，上限 50。满好感邀约增加 0，仍消耗一步。邀约技能通过 `action_kind = invite` 的 `ACTION_BEFORE`／`ACTION_AFTER` 触发，不触发任务限定技能。
- 当前接入年度作品选择、岗位、任务、邀约、日历推进、年末评奖与两页三年结算；邀约由玩家手动选择，尚未接入玩家自动存档／继续游戏入口。前两次跨年后新作品的属性与 Bug 从零开始，上一年的产出与评奖结果归档保留。

## 招募与年初加入事件

- `ClubGame.fresh()` 创建十名候选人的固定状态，`members[i].recruited` 全部为 `false`；开始界面通过 `ClubGame.start_with_members([id1, id2])` 校验两名不同员工并创建已加入这两人的新游戏。主场景仍保留十个员工节点及其位置，运行时仅显示已加入者；排期中的角色圆形、月度工作展示、任务、邀约、学习、技能触发及团队加成都只处理已招募员工。
- 正常开局已有两名所选员工；底层仍支持无人社团状态：排期中仍可点击“下一回合”，不产生工作灵感，正常恢复行动步数；作品没有员工产出，直接跳过空的工作展示。十二月仍正常评奖。
- 前两年十二月结算后只读取刚结束的上一年作品，按类型或题材的显示名匹配候选人的喜好，至少命中一项即符合招募条件。只在未加入者中筛选，无候选跳过，一人加入一人，两人全部加入，超过两人不放回随机选择两人。随机依据本局 ID 与加入年份，抽选结果同时持久保存，重新显示或读档不会重抽。
- 前两年顺序固定为“十二月工作（无人跳过）→ 年末评奖 → 新年逐人加入事件 → 新一年项目选择”；第三年改为评奖后进入结算。窗口显示角色姓名与人物表 `join_text`，空文本或纯空白显示“加入文本”；点击“确认加入”后该角色才入社，没有拒绝选项。全部确认前禁止新一年立项。

## 调试功能（开发版）

主界面左上角的“调试”按钮（或 **F8**）打开调试面板。它只用来搭建测试条件，不参与正式玩法：只替换当前状态快照，不改结算公式、好感上限与技能费用。

- **改当前作品属性**：游戏性、创新性、表现力、Bug 各一行。输入数值后点“增加”在当前值上叠加、点“设为”直接替换，按回车等同“增加”；结果限制在 0～100000，与 `ClubGame` 的写入上限和 `valid_state()` 的取值范围一致。非数字、未知属性与未立项都会被拒绝并给出提示，改动立即刷新主界面属性栏，不消耗行动步数、不推进月份、不触发技能与岗位结算。
- **调整当前时间**：填本年更晚的月份后点“跳转”（附“跳到 12 月”快捷按钮）。跳转只改月份并把行动步数恢复为 1，**不补算**跳过月份的产出、灵感与奖励，年度任务的已用次数保留，因此跳到 12 月后可以直接测试年末评奖。年份由当前进度决定、面板只显示不能改：**跨年与回退都被直接拒绝**，被拒绝时月份不变并显示原因。跳转后的状态仍然通过 `ClubGame.valid_state()`。
- **全员满好感模式**：调试启用时默认开启。打开面板时仅把已招募员工的好感临时写成上限 50，未招募者保持原值，面板同时显示套用结果；关闭时按开启前记录的值恢复好感。满好感沿用现有规则提供每点好感 1% 增幅、解锁 20／50 好感技能位，但**不免费习得技能、也不改变习得费用**。这条路径只在打开调试面板时经过，普通游玩与正式玩法数值不会被调试改动。

调试面板打开时压暗并挡住身后主界面，点界面外、按 Esc 或点“关闭”都能收起；面板打开期间排期、人物页、任务与邀约都不会被执行，任务播放、工作展示与年末评奖期间也不能打开面板。

### 打包正式版怎么关

开关只有一处：`scripts/debug/debug_config.gd` 的 `ENABLED`。

```gdscript
static var ENABLED := false
```

改成 `false` 后主界面不会创建“调试”按钮与面板，F8 不回应，`DebugTools` 的全部入口（改属性、跳月份、满好感）直接拒绝——隐藏界面不等于功能失效，底层同样会拒绝。另有一道不用人工检查的保险：`debug_config.gd` 的 `ALLOW_IN_RELEASE` 为 `false` 时，导出到 Release 模板后即使忘了关 `ENABLED`，调试功能也不会生效（`OS.is_debug_build()` 在编辑器与开发版模板里为 true）。

默认新界面仍未接入玩家存档入口，调试改动只影响当前内存状态。

## 绵羊梦游者的技能

2026-10-13 程序答复确认：好感门槛 0／20／50，梦想家可由任意社员使用，睡着不消耗年度任务次数。

- **白日梦**：0 好感自动生效，自己的任务和月末职责分别有 50% 概率睡着。睡着取消该次任务或自己的全部岗位贡献；睡着者不获得该次工作灵感，其他成员的贡献与灵感判定、邀约不受影响。睡着的任务仍消耗行动步数，年度任务次数保留，下个月恢复步数后可重试。
- **梦境讲述**：20 好感后花 10 灵感习得。每次睡着使自己脑洞白值 +10、其他在岗成员 +5；增长只写本局成员状态，不改人物资料表，同局跨年保留，新游戏清零。
- **梦想家**：50 好感后花 20 灵感习得。每次睡着为当前作品建立下一次任务产出 ×2 的标记，已有标记时不叠加。任意社员下一次成功任务会使用标记，任务睡着则保留；邀约和月末工作不使用标记。翻倍涵盖任务作品增量及任务灵感，含前后阶段技能发放的同类增量；好感、永久能力与每月工作灵感不翻倍。标记按作品 ID 和年份隔离，跨年清除。

随机以本局 ID、年月、结算阶段、人物 ID 为依据，同一输入的预览、提交和保存后重算得到相同结果。工作和任务结果会显示睡着、成长及翻倍使用提示，人物页同步刷新白值。存档版本为 6；默认新界面仍没有自动存档入口。

`tests/test_sheep_skills.gd` 已加入测试启动器，覆盖三技能、费用与门槛、仅取消本人、任务年度次数、全队成长、任意社员使用标记、不可叠加、跨年和新局、存档恢复、随机预览一致以及结果界面。

if await TextConfirm.ask("要覆盖当前进度吗？"):

## 三年结算与排行榜

- 年限统一由 `ClubGame.MAX_YEARS = 3` 定义。第三年十二月完成工作与评奖结算后，模型进入 `phase = finished`，日历停在第 3 年 12 月，行动步数为 0，第三年作品属性保留；不生成第四年项目或加入事件。排期推进、立项、任务、邀约、职责调整、技能学习和调试修改均被拒绝。
- 第三年评奖最后一页的“进入下一年”改为“结算”，点击进入全屏结算页。第一页按年份展示三个项目的完整名字、类型／题材、游戏性、创新性、表现力、Bug 与项目得分。`ClubGame.settlement_score(work)` 使用原始归档属性计算 **游戏性 + 创新性 + 表现力 − 10 × Bug**，允许负分，不套用评奖技能的分数修正、bonus 或 BUG灾难 折半。
- `ClubGame.settlement_summary(state)` 返回隔离的三年快照与三年得分之和；只有终局可读取。内部运算及排序保留小数，界面沿用 `number_display.gd` 的向下取整规则，合计后再取整，不先把单项或各年显示值取整相加。
- 第二页将玩家“你”的三年总分插入九名制作组人员记录，从高到低排序，以金色突出玩家行。同分并列（例如 1、1、3），同分行按制作组录入顺序排列，玩家在同分制作组记录之后。可以用页签、上一页／查看排行榜切换，内容超出时纵向滚动；第二页可返回开始页重新开局。
- 九名制作组人员在 [`data/leaderboard.json`](./data/leaderboard.json) 中预填 `name` 和 `score`；当前“待录入 01”～“待录入 09”及 0 分均为占位，请替换。`score` 是与玩家同口径的三年总分，支持负数与小数。必须恰好九条、名字非空且不重复，不能使用保留名“你”，分数必须为有限数字。配置损坏时提示成绩暂不可用并仅显示玩家成绩，不阻断作品回顾。
- 终局沿用状态版本 6，新增合法阶段 `finished`，存档校验要求第三年十二月、行动步数为 0、三个年度结果齐全且作品快照与档案一致。旧版本错误推进到第四年及以后的状态不再接受；原有第一年至第三年的有效进度仍可读取。新界面仍未接入自动存档。

## 年度作品资料

- `scripts/game_catalog.gd` 是新界面的类型／题材选项来源。存档使用稳定 ID（例如 `narrative`、`fantasy`），界面显示名和排列顺序独立；未来改文案或换排列不会改变已保存作品。ID 删除或重命名时须增加显式迁移，当前非法 ID 会被存档校验拒绝。
- `ClubGame.fresh()` 初始化新游戏，内含 `annual_project_schema: 1` 和 `annual_projects: {}`。按年份字符串存一份确认后的作品资料：`annual_projects["1"] = {id, year, title, genre_id, topic_id}`。作品 ID 由本局 `run_id` 和年份构成，不以可重复的名字充当标识；作品确认后当年不可重复提交或覆盖。
- `ClubGame.select_project(state, title, genre_id, topic_id, expected_year)` 是唯一确认入口：校验当前年一月、选项和名字，以深复制写入档案，触发 `PROJECT_BEFORE`／`PROJECT_AFTER`，不消耗行动步数或月份。输入中的草稿由选择页自己保存，未确认内容不会成为作品属性。
- `ClubGame.project_for_year(state)` 返回当前年份的档案副本；传入第二个年份参数可读取历史作品。`ClubGame.needs_project_selection(state)` 判断当年是否待选择，不额外保存容易失步的“当前作品”副本。招募、偏好、评奖和界面应使用这个入口，不直接读取按钮索引或 UI 文本。
- 技能上下文提供 `project` 快照、`project_id`、`title`、`genre_id`、`topic_id`；`genre`、`topic` 则提供对应显示名以兼容已有条件写法。岗位、任务及邀约报告携带结算时的 `project` 快照，十二月报告不会随着日历进入次年而变成新作品。
- 根字段只有新游戏需要的内容：`version`、`phase`（setup／ready／finished）、`year`／`month`、`inspiration`、`action_steps`、`run_id`、`members`、`work`（游戏性／创新性／表现力／Bug）、`skill_runtime`、`skill_log`、`annual_project_schema`、`annual_projects`、`annual_results`、`recruitment`；不存在 `title`／`genre`／`topic`／`history`／`report`／`claimed` 等旧原型字段。存档版本为 6，年度档案使用独立结构版本 1。
- `SaveStore.save_run()` 可直接序列化整个状态，`load_run()` 通过模型校验恢复所有年度档案及待选择状态，测试已覆盖单年、多年、未知结构版本、非法 ID 和历史隔离。默认新界面仍没有接入玩家自动存档或继续游戏入口；不能据此认为退出后会自动保存。跨年时上一年的产出、分数、奖项与特质归档到 `annual_results`，新作品的属性与 Bug 从零开始。
