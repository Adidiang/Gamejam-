# 灵感涌现ing

Godot 4.7.2 / GDScript 原生游戏。默认运行新的界面骨架，此前的一年可玩原型 v0.1 保留在 `scenes/main.tscn`。

## 当前界面入口

- `scenes/interface_shell.tscn` 为默认主场景，`scripts/interface_shell.gd` 管理界面切换。
- 开始界面只有空白背景与一个“开始游戏”按钮。
- 点击开始后先进入全屏游戏选择界面：自由输入作品名，不沿用旧原型的 18 字截断；类型为 ACT、射击、RPG、策略、模拟经营、剧情向，题材为奇幻、科幻、现代、历史、惊悚。两组各单选一个，支持切换和实时预览；空白名字或选项未完成时不能确认，确认时去掉名字两端空白。每年十二月工作展示确认后重新进入下一年的选择页，清空草稿；未确认时不能进入排期、人物互动或推进月份。
- 选择确认后进入全屏主界面，四个可点击矩形分别对应人物 a、b、c、d，背后铺满活动室背景图。已配置立绘的人物把立绘显示在矩形内并保持比例完整显示，入口默认除立绘外全透明（不画卡片底色、边框和焦点框），只在鼠标悬停时把光标变成手型；未配置立绘的人物保留编号矩形。
- 主界面背景由 `scenes/interface_shell.tscn` 里 `MainScreen/Background` 这个 TextureRect 节点承载，取自 `assets/backgrounds/clubroom.png`，保持比例铺满画面并裁掉多余部分；因此在编辑器里打开该场景就能对着背景图调人物矩形（`MainScreen` 默认隐藏，调布局时先在检查器里勾上 Visible，调完再取消并保存）。`scripts/interface_shell.gd` 启动时把图片写进该节点，图片缺失或资源类型不对时只输出警告、隐藏该节点并回退纯色底，不报错。开始页与人物页暂时使用纯色底。
- 人物入口的立绘由 `scenes/interface_shell.tscn` 里 `MainScreen/CharacterA`～`CharacterD` 下的 `Portrait` 子节点承载，`scripts/interface_shell.gd` 启动时按人物表路径写入。配好立绘的入口由该文件的 `_style_portrait_button()` 改成除立绘外全透明，没有立绘时隐藏该子节点、保留原矩形与编号文字，不报错。默认不画焦点框，把 `scripts/interface_shell.gd` 里的 `PORTRAIT_FOCUS_HINT` 改成 `true` 可给键盘／手柄焦点加一圈金边。
- 人物资料统一填写在 [`data/characters.json`](./data/characters.json)，字段与添加方式见 [`data/README.md`](./data/README.md)。人物 a 已按绵羊梦游者资料填入“代号sheep”，编程 10、脑洞 100、美术 20、音乐 10，题材偏好为奇幻、科幻；初始好感为 0，未指定的类型偏好和其他修正留空。三个技能只填白日梦、梦境讲述、梦想家，人物页显示“机制待实现”，不执行效果或收取灵感。b、c、d 仍为空白、零能力占位；a、b、c 已配置立绘，d 尚未配置。
- 人物页显示编程、脑洞、美术、音乐、好感度、偏好、三个技能位、其他修正和一张立绘。四项属性各显示两列：第一列“白值”是人物表基础属性，第二列“增幅后”用绿色显示计算增幅后的最终值，悬停卡片可看到计算说明。每个技能分别显示名字、介绍和吐槽。其他修正仍为说明文本；立绘路径为空时显示占位区域。
- 新界面的状态由 `ClubGame.fresh()` 初始化，好感度初始为 0、上限 50。能力分两层：`ClubGame.base_ability()` 返回白值，只装人物表基础属性和后续“直接加值”；`ClubGame.ability_bonus()` 汇总百分比增幅，目前是好感增幅（每点好感 1%，满好感 +50%），后续技能百分比在这里相加；`ClubGame.ability()` 用「白值 × (1 + 增幅合计)」得到最终值，打开人物页时刷新。百分比对白值只乘一次，直接加值不会被再次放大。
- 每人三个技能位，按用户最新要求在 0、20、50 好感度解锁，原来的技能 4 与 100 门槛已删除。自动技能达标生效，付费技能显示按配置消耗灵感的习得按钮，不消耗月份。技能填写与代码架构见 [技能系统指南](./scripts/skills/README.md)。点击“关闭”返回主界面。
- 默认全屏启动，按屏幕比例自适应布局；Alt+F4 可退出。
- 主界面右上角显示“第 x 年 x 月”，直接读取 `ClubGame.fresh()` 的年份与月份，不跟随系统时间，点击排期中的“下一回合”时推进月份，12 月后日历进入下一年 1 月。
- 时间下方显示社团当前拥有的灵感点数。灵感是可获得、累积及消费的全局整数资源，保存在状态根字段 `inspiration`，不属于人物或作品；定义集中在 `ClubGame.INSPIRATION`。沿用初始 2 点、每回合获得 1 点、上限 10000 点。`gain_inspiration()` 与 `spend_inspiration()` 提供不消耗月份的获得／消费入口，拒绝负数及余额不足的消费；技能、奖励和每月结算共用同一余额，获得或学习技能后刷新显示。
- 主界面下方显示当前作品：第一行是作品名字与类型题材（读当年作品档案 `annual_projects` 的 `title`／`genre_id`／`topic_id`，经 `GameCatalog.display_name()` 换成显示名；旧原型状态没有档案时回退到 `title`／`genre`／`topic`），第二行是游戏性、创新性、表现力与 Bug 四项属性。数值只读自模型 `work` 快照，界面不参与结算；表现力用 `ClubGame.performance()` 推导（含任务直接产出与视觉／听觉换算），所以和本月工作里“作品累计”的一行保持一致。属性栏排在右下角“排期”按钮左侧，随 `refresh_time()` 与年月、灵感一起刷新，结算、任务产出、进入主界面与每年立项后都会同步，不遮挡排期按钮或人物入口。
- 主界面右下角“排期”按钮打开工作分配表。职责调整不消耗月份、不触发结算，只改变本轮结算时各岗位的人选。
- 工作分配表是居中、非全屏的弹窗：背景压暗并被遮罩挡住下层输入，四个职责方框横排、名称显示在方框上方，角色用圆形的编号表示。拖动圆形，或点击拿起后再点击放下，两种方式都能移动；只要圆形中心落在某个方框内就调整职责（方框四边同样算落点），落在框外或被规则拒绝时回到拿起前的位置。没有拿起角色时点击界面外关闭，拿起后点击界面外先取消再关闭，拖到界面外松开则回到原位并保持弹窗打开，按 Esc 或右键取消拿起。
- 职责调整由 `ClubGame.assign()` 判定：立项准备和每月准备阶段都能自由调整，报告与结局阶段会被拒绝；新界面的岗位结算不隐式选择成员任务或触发立项，仍保留当前可调整阶段；工作展示期间遮挡下层入口并阻止再次结算。
- 工作分配表右下角“下一回合”关闭排期、一次性结算全员岗位产出并推进日历，然后打开“本月工作”。标题标注刚结算的年月；左侧按人物表顺序排列头像（无立绘时显示编号），右侧显示职责以及游戏性、创新性、视觉、听觉、新增 Bug、修复能力。下一人的数值先从零递增到完整成果，再开始滚动；滚动前上下两人的工作成果均已展示完成，每人的停留等待为 0.375 秒，全部完成后可点击“确认”；列表也可滚动回看。修复能力显示原始贡献，实际 Bug 按全员同时结算并以零为下限，底部显示作品累计值和本轮获得／当前拥有的灵感。未填能力的人物仍完整播放零产出。
- 人物页的“分配任务”打开右侧部分宽度的任务列表，人物页保持可见；点击列表外任意位置只关闭列表、返回人物页，不触发背后的按钮。列表显示当年所有可用任务，已完成任务对全员隐藏，无任务时显示空状态。
- 选择任务调用 `TextConfirm.ask()`：取消只关闭确认框，确认关闭确认框与任务列表并打开执行界面。执行界面左侧为执行成员立绘（缺图显示编号），右侧先保持空白，下方真实进度条在 1 秒内从 0 到 100，完成后只显示本次任务产出及任务技能带来的实际变化，不显示职责产出或每月灵感。播放时不能提前关闭或重复执行；完成后点“确认”返回主界面。
- 按用户最新规则，全社团每回合有隐藏的行动步数，默认为 1。任务消耗 1 步，但不推进月份；步数为 0 时，所有成员的“分配任务”按钮变灰，点击弹出“本回合已行动”小框，点击任意位置或 2 秒后自动关闭，不能打开列表。排期中的“下一回合”仍是月份推进入口，同时结算全员职责、获得每月灵感、把行动步数恢复为 1；未用的步数不累积，玩家也可以未行动直接进入下一回合。
- 当前任务只有“美术概念设计”，无前置、消耗 1 行动步数。每款游戏（按年份）全社团只能执行一次，换成员或下个月恢复步数不会恢复任务次数，排期跨年后才恢复。产出使用好感增幅后的属性：表现力＝脑洞＋美术；创新性＝表现力×clamp(脑洞÷max(美术, 1), 0.1, 2)。分母最低取 1，系数最低 0.1、最高 2，均为用户确认的规则；系数限制仅适用于此任务。
- 隐藏步数保存在根字段 `action_steps`，`ClubGame.action_steps()` 读取余额，旧状态缺字段时按 1 处理。任务次数保存在可选根字段 `completed_tasks`，按年份键记录任务 ID；直接表现力保存在 `work.p`，与现有视觉／听觉推导出的表现力相加，避免将任务产出误当视觉或被二次折算。`ClubGame.execute_task()` 统一校验余额、次数、阶段和预期年月，只结算任务及任务阶段技能、扣减步数；界面只播放已确定的报告。`advance_work()` 负责职责、每月灵感、日历推进与步数重置，`available_tasks()` 提供列表。
- 人物页新增与“分配任务”并排的“邀约”按钮。点击后使用通用确认框，取消留在人物页且不消耗步数；确认后调用 `ClubGame.execute_invite()`，与任务共用一次行动结算及执行展示界面，左侧立绘、右侧先空白、下方 1 秒进度条，完成后显示好感变化及邀约技能带来的实际变化。执行后返回主界面，年月保持不变。
- 邀约与任务共用全社团 `action_steps`：任一行动消耗 1 后两个按钮均变灰，点击均显示“本回合已行动”小框（点击任意位置或 2 秒后消失）。邀约不结算职责或每月灵感，不登记年度任务次数，恢复步数后可在同年再次邀约。好感由 `invite_gain()` 固定增加 10，连续邀约同一成员或更换成员均不改变增量，上限 50。满好感邀约增加 0，仍消耗一步。邀约技能通过 `action_kind = invite` 的 `ACTION_BEFORE`／`ACTION_AFTER` 触发，不触发任务限定技能。
- 当前接入年度作品选择、岗位、任务、邀约与日历推进；邀约由玩家手动选择，没有接入评奖、三年结束或玩家存档入口。选择时触发已有立项技能，不新增成员偏好奖励数值或招募规则。跨年沿用现有日历行为，作品总值暂不自动清空。旧原型的一年完整流程保留，其旧行动列表不作为当前任务入口。
- 旧原型可在编辑器中打开 `scenes/main.tscn` 后按 F6 运行。下文玩法、存档与原有测试描述对应旧原型。

## 通用文本确认框

`scenes/text_confirm.tscn` 已注册为全局单例 `TextConfirm`，任何脚本或场景都能直接调用，不必自己挂节点或搭界面：

```gdscript
if await TextConfirm.ask("要覆盖当前进度吗？"):
	print("玩家点了确认")
```

- 参数就是正文：传入的这段文本显示在确认框里，下方固定是「取消」（左）和「确认」（右）两个按钮。
- 点「确认」返回 `true`，点「取消」或按 Esc 返回 `false`；界面只负责提问和返回结果，不修改任何游戏数据。
- 宽度固定，高度按文本行数自适应；超过上限的长文本在正文里滚动查看，两个按钮始终留在框内。
- 打开时暂停场景树、压暗并挡住下层界面，关闭后还原暂停状态和打开前的焦点，不会点穿到排期界面或主界面。
- 同一时间只显示一条：上一条还没回复时，新请求先排队，依次显示并各自只收到自己的结果。
- 默认焦点在「取消」，按 Esc 等同取消；点击确认框外的遮罩不会关闭。
- 任务分配已使用此界面确认执行；其他流程也可按需调用。

## 已实现

1. 年初输入作品名，选择类型与题材，预览并结算社员偏好。
2. 四名成员共用新人物表；绵羊梦游者已填写基础能力、姓名、题材偏好与三个技能名字，其余人物资料待填写。
3. 点击社员卡或活动室中的成员进行选择；免费调整玩法、美术、音效、修复岗位。
4. 每月一次行动：邀约、玩法打磨、原型实验、风格设计、配乐制作、集中测试。
5. 执行前预览完整回合的全员产出、Bug 数值变化和灵感获得。
6. 好感提高能力，三技能系统接入实际结算；自动技能和付费习得共用执行器，费用逐技能配置，旧的单技能布尔状态和固定专长加成已删除。好感上限为 50、每点好感提供 1% 能力增幅，每人三个技能位；能力分为白值与增幅后两层显示。
7. Bug 是暂没有用途的白板数值，仅保留增加、修复和展示；不影响开发效率、评分、获奖条件或奖励。
8. 4 月与 8 月试玩达标奖励、12 月年末评奖、三项评分、获奖条件与历史手记；试玩只按三项作品属性奖励灵感。
9. 自动存档、备用存档恢复、继续游戏与重新开始。
10. 原创代码绘制的活动室和人物，以及可关闭的合成按钮音效。

## 操作与目标

点击一名成员，在右侧选择行动，然后点击“执行行动，结束本月”。每次执行之后，四名成员都会按各自岗位自动开发。调整分工、查看说明和学习技能不消耗回合。

最佳游戏奖需要总分不低于 80，游戏性、创新性、表现力的评分均不低于 50。没拿到最佳游戏也有完整结局，可以查看全年制作手记后再挑战。

表现力由视觉与听觉共同决定：`0.5 × (视觉 + 听觉) + min(视觉, 听觉)`。原始属性 210 点对应单项评分 100；综合权重为 40% / 30% / 30%，Bug 不扣分。

## 第一版范围

这版验证一年 12 回合主循环。每名成员已有 0／20／50 好感门槛的三个技能位，执行器、学习状态和触发点已实现，具体角色技能仍待填写。新界面的工作分配表已支持拖动与点击两种方式调整职责，“下一回合”已接上月份推进与岗位结算；调整职责本身仍不消耗月份。三年继承、两名新成员招募暂未加入。设计要求以策划案及用户最新规则为准，数值仍需要真人试玩平衡。

界面为 1440 × 900 设计画布，保持比例缩放。Windows 使用系统微软雅黑，不将系统字体打包再分发。若移植到没有中文系统字体的平台，需要添加授权允许分发的中文字体。

## 存档

旧原型工程版保存至 `saves/club.json`，上一份有效存档备份为 `saves/club.json.bak`，测试数据单独写入 `qa/`。好感度上限改为 50、技能位由四个改为三个后，存档版本升级为 4，版本 1～3 存档不再读取；在岗人物编号或已习得技能不匹配的存档也不加载。技能习得、次数和临时修正均随存档保存。新界面暂不读写玩家存档。

## 年度作品资料

- `scripts/game_catalog.gd` 是新界面的类型／题材选项来源。存档使用稳定 ID（例如 `narrative`、`fantasy`），界面显示名和排列顺序独立；未来改文案或换排列不会改变已保存作品。ID 删除或重命名时须增加显式迁移，当前非法 ID 会被存档校验拒绝。
- `ClubGame.fresh_annual()` 初始化新流程，新增 `annual_project_schema: 1` 和 `annual_projects: {}`。按年份字符串存一份确认后的作品资料：`annual_projects["1"] = {id, year, title, genre_id, topic_id}`。作品 ID 由本局 `run_id` 和年份构成，不以可重复的名字充当标识；作品确认后当年不可重复提交或覆盖。
- `ClubGame.select_project(state, title, genre_id, topic_id, expected_year)` 是唯一确认入口：校验当前年一月、选项和名字，以深复制写入档案，触发 `PROJECT_BEFORE`／`PROJECT_AFTER`，不消耗行动步数或月份。输入中的草稿由选择页自己保存，未确认内容不会成为作品属性。
- `ClubGame.project_for_year(state)` 返回当前年份的档案副本；传入第二个年份参数可读取历史作品。`ClubGame.needs_project_selection(state)` 判断当年是否待选择，不额外保存容易失步的“当前作品”副本。未来招募、偏好、评奖和界面应使用这个入口，不直接读取按钮索引或 UI 文本。
- 技能上下文提供 `project` 快照、`project_id`、`title`、`genre_id`、`topic_id`；`genre`、`topic` 则提供对应显示名以兼容已有条件写法。岗位、任务及邀约报告携带结算时的 `project` 快照，十二月报告不会随着日历进入次年而变成新作品。
- 旧原型的根字段 `title`／`genre`／`topic` 和三项旧选项只供旧原型兼容，不作为年度流程的数据来源。存档总体仍为版本 4，年度档案使用独立结构版本 1；缺少年度字段的原有版本 4 状态仍按旧原型处理，不自动猜测新类型／题材。
- `SaveStore.save_run()` 可直接序列化整个状态，`load_run()` 通过模型校验恢复所有年度档案及待选择状态，测试已覆盖单年、多年、未知结构版本、非法 ID 和历史隔离。默认新界面仍没有接入玩家自动存档或继续游戏入口；不能据此认为退出后会自动保存。跨年只新增作品身份资料，累计产出仍沿用当前实现，年度清空／归档产出与评奖流程待后续明确。
