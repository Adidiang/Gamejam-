# 美术资源说明

`assets/` 存放游戏实际使用的图片。目录按用途划分，代码只引用工程内的 `res://assets/...` 路径，不要写入 Windows 绝对路径。

| 目录 | 用途 | 引用方式 |
| --- | --- | --- |
| `portraits/` | 人物立绘，一人一张，主界面入口除立绘外全透明 | 在 `data/characters.json` 的 `portrait` 字段填写路径 |
| `backgrounds/` | 界面背景图，一个界面一张 | 界面代码中的背景路径常量 |

`icon.svg` 是工程图标。

## 添加立绘

放入 `assets/portraits/`，让 Godot 导入，然后把该人物的 `portrait` 填为例如 `res://assets/portraits/a.png`。主界面里配好立绘的入口默认除立绘外全透明，这张图会直接叠在活动室背景上，所以立绘轮廓之外必须是真正的透明像素，不要保留白底。详细说明见 [`data/README.md`](../data/README.md)。

## 添加背景

放入 `assets/backgrounds/`，让 Godot 导入，然后在界面代码中引用。按界面内容命名，一个界面一个文件：

| 文件 | 对应界面 |
| --- | --- |
| `clubroom.png` | 主界面（策划案中的活动室场景） |

后续界面沿用同一目录，例如 `work_table.png`、`award_ceremony.png`。

- 设计画布为 1440 × 900（16:10）。建议素材为 2560 × 1600，保持同一比例，为全屏显示留出清晰度余量。
- 当前 `clubroom.png` 为 1448 × 1086（约 4:3），比设计画布更高：全屏铺满时会裁掉上下两端，16:9 约各裁 12%，21:9 约各裁 22%。裁掉的是天花板和地面，主要场景仍在画面内。想减少裁切，换成 16:10 或更宽的素材即可，代码无需改动。
- 只画场景，不在背景图里画人物和界面元素，方便调整人物站位和交互区域。
- 四周留出可裁切空间：窗口按屏幕比例放大并裁切画面，主要场景内容放在中间。
- 背景缺失时界面回退为纯色底，不报错。

## 格式

- 背景图：PNG，或不带透明通道的高质量 WebP。
- 人物立绘：带透明通道的 PNG，人物轮廓之外保持透明。

PSD、Krita 等分层源文件不放入 Godot 工程，另存于工程目录之外；工程内只保留导出后的成品图。Godot 导入图片时会生成同名 `.import` 文件，该文件需要提交。
